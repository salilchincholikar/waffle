# Development

## Requirements

- **macOS 26 or later.** The app is built for macOS 26 (Tahoe) and uses its AppKit APIs.
- **Rust:** stable, via [rustup](https://rustup.rs).
- **Xcode Command Line Tools:** run `xcode-select --install`. Full Xcode is optional. `macos/Package.swift` opens directly in Xcode if you prefer it.
- **Python 3:** only needed to regenerate test files.

## Everyday commands

```sh
make app          # build/Waffle.app (release)
make run          # build and open it
make test         # Rust tests + Swift tests
make lint         # rustfmt check + clippy -D warnings
make selftest     # drive the real app (debug build) through editing, undo, revert, save
make help         # everything else
```

The Rust engine is always built in release mode, because the Swift package links `target/release/libwaffle_ffi.a`.

## Where things live

| You want to… | Look in |
|---|---|
| Fix a formula function | `crates/waffle-calc/src/f_*.rs` (tests in `tests.rs`) |
| Change how numbers/dates display | `crates/waffle-numfmt` |
| Fix reference shifting on insert/delete/rename | `crates/waffle-refs` |
| Change an editing operation (sort, fill, clean-up…) | `crates/waffle-core/src/ops.rs` |
| Change what the grid shows for a cell | `crates/waffle-core/src/view.rs` |
| Fix xlsx/CSV reading or saving | `crates/waffle-io/src/{xlsx,csv.rs}` |
| Add something the app calls into Rust | `crates/waffle-ffi/src/lib.rs` (the header regenerates on build), then `macos/Sources/WaffleBridge/Book.swift` |
| Change drawing, mouse or keyboard | `macos/Sources/Waffle/Grid/` |
| Change the sheet's colours (incl. the dark sheet option) | `Grid/SheetPalette.swift` |
| Change the title bar (file tabs, Find, sheet tools) | `Window/SheetWindowController+TitleBar.swift`, `Window/TitleTabs.swift` |
| Change how file tabs group and switch | `Window/WindowTabs.swift` |
| Change the formula row's formatting controls | `Window/SheetWindowController+FormatBar.swift` |
| Change Find & Replace | `Find/FindBar.swift` (the fields), `Find/FindCenter.swift` (search across all open files) |
| Add a menu command | `App/MainMenu.swift` plus an action in `Window/SheetWindowController+*.swift` |

## The C interface

`crates/waffle-ffi/include/waffle.h` is generated by `build.rs` (cbindgen), so never edit it by hand.

- Every exported function catches panics. A Rust bug shows an error dialog instead of crashing the app.
- Strings returned to Swift point into a per-document buffer that is valid until the next call returning a string, so Swift copies them immediately.

## Debug hooks

Debug builds (`make app-debug`) respond to these environment variables. Release builds compile them out.

| Variable | Effect |
|---|---|
| `WAFFLE_SELFTEST=/tmp/out.xlsx` | Runs a scripted session: typing, formatting, undo/redo through the menu path, paste, insert, sort, find, filter, revert. Prints `ok`/`FAIL` lines, saves, and exits |
| `WAFFLE_SNAPSHOT=/tmp/shot.png` | Renders the window to a PNG and quits. Optional extras: `WAFFLE_SNAPSHOT_SHEET=Name`, `WAFFLE_SNAPSHOT_SELECT=B2:D6`, `WAFFLE_SNAPSHOT_SCROLL=x,y`, `WAFFLE_SNAPSHOT_ZOOM=1.5`, `WAFFLE_SNAPSHOT_SIZE=1400x800`, `WAFFLE_SNAPSHOT_APPEARANCE=light\|dark`, `WAFFLE_SNAPSHOT_FIND=1` (Find and Replace open), `WAFFLE_SNAPSHOT_FINDTYPE=text` (types into Find), `WAFFLE_SNAPSHOT_COLW=px` (then resizes column A) |
| `WAFFLE_SNAPSHOT_STAY=1` | Keeps the app open after the snapshot, so the real window can be captured with `screencapture -l <window id>` (the in-app PNG can't draw native controls exactly) |
| `WAFFLE_BENCH=1` | Times 40 full redraws at different scroll positions |
| `WAFFLE_TABTEST=query` | With several files as arguments: reports tab grouping and steps a search across all of them |
| `WAFFLE_MENUDUMP=1` | Prints the File and Edit menus |

Example:

```sh
make app-debug
WAFFLE_SNAPSHOT=/tmp/s.png build/debug/Waffle.app/Contents/MacOS/Waffle "$PWD/testdata/files/rich.xlsx"
```

## Performance checks

```sh
make corpus-large                          # generates 10k×1k and 200k-row files (once)
make probe FILE=testdata/files/large_10k_x_1k.xlsx
```

`probe` prints time to first rows, full load time and memory. Reference numbers on an Apple Silicon Mac: first rows in about 25 ms, full load in 1.7 s, about 90 MB.

## Screenshots

`tools/screenshots/make_demo.py` writes demo workbooks with made-up data to `build/demo/` (it needs `xlsxwriter==3.2.9`). Use those, never real files, for README and website screenshots. Open them in a debug build with the snapshot hooks above and `WAFFLE_SNAPSHOT_STAY=1`, then capture the window with `screencapture -o -l <window id>`.

## Releasing

`.github/workflows/release.yml` builds and publishes a release when a `v*` tag is pushed.

1. Set the version in `Cargo.toml` (`[workspace.package]`) and `macos/Resources/Info.plist` (`CFBundleShortVersionString`, and bump `CFBundleVersion`). The workflow refuses a tag that doesn't match both.
2. Give the version's `CHANGELOG.md` section its date (`## 0.1.0 — 2026-09-28`); that section becomes the release notes.
3. Commit, then `git tag v0.1.0 && git push origin v0.1.0`.

The workflow runs lint, tests and the self-test, builds `Waffle-<version>-arm64.zip` with a SHA-256 checksum, and creates the GitHub Release. The website's Download button always points to the latest release.

## Website

`site/` is the GitHub Pages site: one static page, no build step, deployed by `.github/workflows/pages.yml` on every push to `main` that touches it (enable it once under Settings ▸ Pages ▸ Source: GitHub Actions). Preview it by opening `site/index.html` in a browser.

- Screenshots live in `site/assets/screenshots/` as WebP (about 170 KB each; macOS's own AVIF encoder writes files Chrome can't decode). The README uses PNG copies (`readme-*.png`).
- The logo files in `site/assets/` are copied there by `make icon`; don't edit them by hand.
- Type is SF Pro Rounded where the system has it (`ui-rounded`), otherwise Nunito, which is self-hosted (`site/assets/fonts`, SIL OFL) so the site makes no third-party requests.
- A custom domain later: add `site/CNAME` with the domain and point a DNS record at GitHub Pages.

## Test files

`testdata/files` holds the corpus. Its README lists the facts each file is built to exercise. The files are generated deterministically by `tools/corpus` (`make corpus`). Large files are git-ignored and generated on demand.
